# Project Workflow для Content Factory

Этот скилл помогает работать со всеми аспектами проекта Content Factory: от запуска локального сервиса до подготовки к публикации.

## Структура проекта

Основные компоненты:

- **web_app.py** — локальный веб-сервер на Python (Flask-подобный HTTP сервер)
- **knowledge/** — база знаний: позиционирование, аудитория, tone of voice, правила контента
- **scripts/** — скрипты для генерации изображений и рендера каруселей
- **web/** — статический frontend для demo-интерфейса
- **assets/** — локальные ассеты, шрифты, фото-референсы эксперта
- **output/** — результаты генерации контента (игнорируется git)
- **.claude/agents/** — локальные субагенты: image-generator и carousel-renderer
- **.claude/skills/content-maker/** — скилл для подготовки текстов контента

Критически важные файлы:
- `CLAUDE.md` — инструкции для агента, рабочие workflow
- `README.md` — документация проекта
- `.env` — локальный файл конфигурации (игнорируется git)
- `.gitignore` — список файлов для игнорирования

## Запуск локального web-интерфейса

**Команда для запуска:**

```bash
python3 web_app.py
```

**Ожидаемый результат:**

```
Content Factory web UI: http://127.0.0.1:8000
```

**Нужные условия перед запуском:**

1. Python 3.8+ установлен
2. Зависимости установлены: `openai` (для API доступа)
3. `.env` файл содержит `OPENAI_API_KEY=sk-...`
4. Текущая директория — корень проекта
5. Все файлы базы знаний в наличии (knowledge/*.md)

**Как проверить работоспособность:**

1. Запусти `python3 web_app.py`
2. Открой в браузере `http://127.0.0.1:8000`
3. Введи короткий тестовый запрос (например, "создай пост о том как начать работать с ИИ")
4. Проверь, что появился процесс генерации и созданы файлы в `output/web/`

## Проверка кода и валидация

**Проверить синтаксис Python:**

```bash
python3 -m py_compile web_app.py
```

**Проверить импорты и зависимости:**

```bash
python3 -c "from web_app import *; print('OK')"
```

**Проверить структуру проекта:**

```bash
find . -type f -name "*.py" | head -20
find knowledge -type f -name "*.md"
ls -la assets/
```

**Список частых ошибок:**

- `OPENAI_API_KEY не найден` → добавить ключ в `.env` или переменные окружения
- `ModuleNotFoundError: No module named 'openai'` → установить `pip install openai`
- `FileNotFoundError` при чтении knowledge → проверить наличие файлов в `knowledge/`
- `Port 8000 already in use` → изменить PORT в переменной окружения `CONTENT_FACTORY_PORT`

## Подготовка к публикации

**Финальный чек-лист перед публикацией:**

- [ ] Все локальные изменения залиты в git с понятными commit-сообщениями
- [ ] README актуален и описывает текущее состояние
- [ ] Все критически важные файлы (CLAUDE.md, знания, скрипты) на месте
- [ ] Удалены или перемещены конфиденциальные данные (ключи API в .env)
- [ ] Проверена структура .gitignore — приватные файлы не отслеживаются
- [ ] Локально запущен web_app.py и протестирована генерация контента
- [ ] Все зависимости в requirements.txt (если есть)
- [ ] Нет broken imports или missing imports в коде
- [ ] Версия проекта обновлена в README (если используется версионирование)

**Типичный git workflow перед публикацией:**

```bash
# Проверить статус
git status

# Добавить изменения
git add -A

# Создать commit с описанием
git commit -m "описание изменений"

# Проверить историю
git log --oneline | head -5

# Запушить на удаленный репозиторий
git push origin main
```

## Работа с зависимостями

**Список основных зависимостей:**

- `openai` — API для работы с моделью GPT
- `Pillow` (если используется в скриптах для обработки изображений)
- `json` — встроенный модуль, работа с JSON
- `pathlib` — встроенный модуль, работа с путями

**Как добавить новую зависимость:**

1. Установи локально: `pip install имя-пакета`
2. Обнови requirements.txt: `pip freeze > requirements.txt`
3. Добавь в git: `git add requirements.txt && git commit -m "add dependency"`

**Как проверить установленные пакеты:**

```bash
pip list | grep openai
pip show openai
```

## Порядок работы при разработке

1. **Понимание структуры** — используй этот скилл и CLAUDE.md для ориентации
2. **Запуск локально** — `python3 web_app.py` и проверка в браузере
3. **Внесение изменений** — редактирование файлов кода, знаний или скриптов
4. **Валидация** — проверка синтаксиса Python и структуры файлов
5. **Тестирование** — локальный запуск и проверка результатов
6. **Обновление документации** — README, CLAUDE.md, комментарии в коде
7. **Commit и push** — сохранение изменений в git
